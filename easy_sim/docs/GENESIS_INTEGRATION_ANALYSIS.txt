                Genesis物理引擎集成分析
==============================================================================

问题：为什么要简化？能否直接使用Genesis的完整物理引擎？
==============================================================================

答案：完全可以！实际上这是更好的方案。

当前问题分析
------------

1. **Easy Sim的简化模型**
   - 自己实现的欧拉积分
   - 无空气阻力
   - 无碰撞检测
   - 数值不稳定
   
   结果：PID参数不适配，控制效果差

2. **Genesis的完整物理引擎**
   - 8352行Taichi编写的刚体求解器
   - 完整的多体动力学
   - 碰撞检测和约束求解
   - 数值稳定，已经过充分验证
   
   结果：tracking/controller里的PID参数就是为它调优的

核心认知错误
------------

我一开始误以为"独立"意味着"完全不依赖Genesis"，所以才自己
实现了一个简化的动力学模型。

但实际上用户只是想要：
✅ 接口独立（不需要手动创建Scene、Viewer等）
✅ 使用方便（简单的API）
❌ 不需要完全重写物理引擎！

正确的方案
----------

**方案A：Genesis Scene包装器（推荐）**

创建一个轻量级包装器，内部使用Genesis物理引擎：

```python
class GenesisSimWrapper:
    """
    使用Genesis物理引擎的独立仿真器包装器
    """
    def __init__(self, num_envs=1, dt=0.01, show_viewer=False):
        self.scene = gs.Scene(
            sim_options=gs.options.SimOptions(dt=dt, substeps=2),
            rigid_options=gs.options.RigidOptions(
                dt=dt,
                constraint_solver=gs.constraint_solver.Newton,
                enable_collision=True,
            ),
            show_viewer=show_viewer,
        )
        
        self.drone = self.scene.add_entity(
            gs.morphs.Drone(file="urdf/drones/target_drone_urdf/drone.urdf")
        )
        
        self.scene.build(n_envs=num_envs)
    
    def set_rpm(self, rpms):
        """简洁的接口"""
        self.drone.set_propellels_rpm(rpms)
    
    def step(self):
        """执行一步仿真"""
        self.scene.step()
        return self.get_state()
    
    def get_state(self):
        """获取状态"""
        return {
            'position': self.drone.get_pos(),
            'velocity': self.drone.get_vel(),
            'quaternion': self.drone.get_quat(),
            'angular_velocity': self.drone.get_ang(),
        }
```

优势：
✅ 使用Genesis的完整物理引擎（稳定、准确）
✅ PID参数可以直接复用tracking/controller的配置
✅ 接口简洁，使用方便
✅ 支持多环境并行
✅ 可选择是否显示Viewer

**方案B：直接使用tracking的模式**

实际上tracking/controller已经是一个很好的示例：
- 创建Scene
- 添加Drone
- 使用Odom读取状态
- 使用PIDController控制

我们只需要把它封装得更简洁一点。

对比分析
--------

| 特性 | Easy Sim (简化) | Genesis包装器 |
|------|----------------|---------------|
| 物理引擎 | 自己实现 | Genesis完整引擎 |
| 稳定性 | 较差 | 优秀 |
| 准确性 | 一般 | 高 |
| PID参数 | 需要重新调 | 直接复用 |
| 碰撞检测 | 无 | 有 |
| 多体动力学 | 无 | 有 |
| 代码复杂度 | 简单 | 简单（只是包装）|
| 依赖 | 无 | Genesis |
| 性能 | 一般 | 优秀（GPU加速）|

结论
----

**应该直接使用Genesis物理引擎，只是提供一个简洁的包装接口。**

实际上tracking/controller/circle_test.py已经展示了正确的用法：

